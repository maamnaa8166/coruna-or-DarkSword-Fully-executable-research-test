## 이 문서는 무엇인가

실제 워터링홀(watering-hole) 캠페인에서 관측된 상업급 iOS 익스플로잇
툴킷 **Coruna**에 대한 심층 연구입니다. 이 툴킷은 WebKit 익스플로잇을
연결해 iOS 13–17에서 완전한 기기 장악을 수행한 뒤, 23개 모듈로
구성된 스파이웨어 시스템을 배포합니다 — 암호화폐 지갑, SMS,
WhatsApp, 사진 앨범까지 — 그리고 도메인 생성 기술 뒤에
C2 통신 트래픽을 숨깁니다.

본 연구는 포획된 툴킷 샘플에 대한 분석에 기반합니다. *"무엇이
전달되었는가"*를 넘어, 이 문서는 그다음 질문에 답합니다: 임플란트는
어떻게 자신의 인프라를 숨기는가, 트래픽은 어떤 모습인가(C2 프로토콜과
90-요청 포렌식 타임라인), 기기에서 악성코드는 무엇을 하는가(모듈
시스템과 앱 트리거형 유출).

## 주요 기능

| 기능 | 세부 사항 |
|------|-----------|
| 지원 iOS 버전 | iOS 13.0–17.2.1, 버전별 익스플로잇 체인 (WebKit 메모리 커럽션 → PAC 우회 → 샌드박스 탈출) |
| 지갑 탈취 | 19개 지갑 앱 — MetaMask, imToken, Trust Wallet, TronLink, BitKeep, TON Keeper, Uniswap, Phantom, MyTonWallet, Exodus, Ronin, Krystal, TonHub, Global Wallet, Coin98, Bitpie, Solflare, OKX (EVM / Solana / TON / Tron / Ronin) |
| 모듈 시스템 | 23개 주입 모듈: 19개 지갑 + WhatsApp (`wap.js`) + SMS (`sms.js`) + SpringBoard 코어 페이로드 (`new.js`) + 설정 수신기 (`helion.js`) |
| 사진 앨범 탈취 | 기기 사진을 암호화된 컨테이너로 패키징하여 대량 유출 |

| C2 통신 | 생성 도메인, 암호화된 POST 트래픽, 앱 트리거형 대량 업로드 |

## 공격 체인 개요

```
피해자가 워터링홀 페이지(위조 등록 사이트) 접속
  └─ 숨겨진 iframe이 난독화된 로더 JS를 로드
      ├─ 1단계 — WebKit / WASM 메모리 커럽션 → 읽기/쓰기 프리미티브
      ├─ 2단계 — PAC 우회 (A12+ 기기)
      └─ 3단계 — 샌드박스 탈출 + 메모리 내 Mach-O 로더
          └─ bootstrap 단계가 암호화된 페이로드 모듈을 전달
              └─ powerd / SpringBoard 주입으로 지속성 확보
                  └─ 생성 도메인의 C2 트래픽
                      └─ 23개 주입 모듈 → 지갑 / SMS /
                         WhatsApp / 사진 앨범 탈취
```

## 핵심 발견 (TL;DR)

1. **전부 정적 암호화 재료.** 이 툴킷은 페이로드, 모듈, 트래픽을
   여러 겹의 암호화로 감싸지만, 사용하는 모든 키 재료는 샘플 자체에
   내장되어 있습니다 — 기기별·세션별 성분은 전혀 없습니다. 암호화는
   전송 난독화일 뿐, 샘플 보유자에 대한 실질 기밀성은 없습니다.
2. **생성 도메인으로 숨겨진 인프라.** C2 도메인은 임플란트에 내장된
   재료에서 필요할 때 생성됩니다: 저가 TLD 아래 15자 랜덤 영숫자
   라벨. 시퀀스가 완전히 결정적이므로, 샘플을 확보한 방어자는
   캠페인의 미래 도메인을 미리 파악해 DNS 계층에서 선제 차단할 수
   있습니다.
3. **C2 프로토콜은 소규모·비대칭적.** 평문 `/vhx` 하트비트, 암호화된
   POST 본문, 고정 크기의 작은 확인 토큰 — 의도적으로 낮은
   프로파일.
4. **유출은 앱 트리거 방식.** 포획 세션에서 암호화폐 지갑 앱을
   실행하자 즉시 하트비트 폭발과 두 번의 대형 암호화 업로드
   (1.8 MB, 624 KB)가 발생했습니다; 사진 앨범도 같은 대량 채널을
   사용합니다.
5. **23개 주입 모듈 중 19개가 지갑 대상**이며 다섯 생태계를 아우르고,
   WhatsApp, SMS, 사진 앨범, SpringBoard 코어 페이로드가 추가됩니다
   — 국가급 첩보가 아닌 대여 가능한 감시 제품입니다.

## 1. C2 프로토콜

9개 엔드포인트, 평문 하트비트 1개, 나머지는 전부 암호화 POST —
의도적으로 최소화되어 있고 회선상 지문화하기 쉽습니다.

| 엔드포인트 | 메서드 | 용도 | 본문 |
|------------|--------|------|------|
| `/vhx` | GET | 하트비트 | 평문 `OK` 응답 |
| `/a` | POST | 등록 / 체크인 | 암호화 |
| `/event` | POST | 이벤트 보고 | 암호화 |
| `/u` | POST | 설치된 앱 목록 | 암호화 |
| `/nb` | POST | 대량 업로드 (사진, 대용량 데이터) | 암호화 |
| `/ub` | POST | 단일 업로드 | 암호화 |
| `/details/<모듈>` | GET | 모듈 다운로드 | 아카이브 형식 페이로드 |
| `/api/ip-sync/sync` | POST | 운영자 측 IP 동기화 | 암호화 |
| `/config` | POST | 설정 송수신 (`config.json`) | 암호화 |

**암호화 POST 채널.** 모든 보고 및 업로드 엔드포인트는 암호화된
본문을 실으며, 키 재료는 캠페인의 모든 샘플에 컴파일되어 있습니다.
응답은 정보를 담지 않는 고정 크기 토큰입니다 — 회신에 일정하고
식별 가능한 형태를 부여하기 위해서만 존재합니다. 설계 목표는
명백히 암호학적 강도가 아니라 낮은 프로파일 트래픽입니다: 이 체계는
가벼운 검사만 막을 뿐이며, 회선상의 형태(아래 탐지 시그니처 참고)가
그 자체로 가장 강력한 포렌식 신호입니다.

**하트비트 수명 주기.** 임플란트는 주기적으로 현재 생성 도메인에
`GET /vhx`를 보냅니다; 살아있는 서버는 평문 `OK`로 응답합니다.
실패하면 다음 생성 도메인으로 넘어갑니다 — 도메인 차단 이후에도
도달 가능하게 유지하는 "데드맨 스위치"이자 수동 DNS 모니터링에
노출시키는 비컨입니다.

**모듈 획득.** 일반 `GET` 요청이 암호화된 아카이브 형식 파일을
반환합니다. 모듈은 지연 로딩됩니다 — 해당 피해 앱이 감지되거나 실행된
뒤에만 요청하므로, 캡처 내 모듈 트래픽은 피해자의 설치된 앱 목록을
직접 반영합니다.

**설정 채널.** 전담 모듈이 모듈별 설정, 스케줄링 파라미터, 도메인
커서 상태를 담은 JSON 블롭을 관리하며 디스크에 캐시합니다; 변경은
재배포 없이 효력을 갖습니다.

**탐지 시그니처.**

- 주기적인 평문 `GET /vhx` → `OK` 교환.
- 갓 등록된 저가 TLD 도메인으로의 고엔트로피 POST 본문.
- 고정 크기, 약 24자 응답 본문.
- 아카이브 형식 바이너리를 반환하는 `.js` 이름의 URL.
- 피해 앱 실행 직후의 암호화 POST 폭발.

## 2. 트래픽 포렌식 — 90-요청 타임라인

워터링홀 페이지부터 안정 상태의 C2까지 — 전체 감염 세션이 분석용으로
포획되었습니다(약 90개 요청). 전체 수명 주기를 축소판으로 보여줍니다.

| 단계 | 트래픽 | 드러나는 것 |
|------|--------|-------------|
| 1. 전달 | 워터링홀 페이지 + 숨겨진 iframe 자산 | 유인책과 익스플로잇 로더 |
| 2. 인프라 | IP 에코 조회, OCSP/CRL 확인, 운영자 동기화 호스트 | 정찰 및 사이드 채널 기록 |
| 3. 임플란트 기동 | 첫 생성 도메인 접촉, 등록, 앱 목록, 모듈 다운로드 | 임플란트가 깨어남 |
| 4. 안정 상태 | 하트비트 루프 + 이벤트 보고, 피해 앱 실행 후 폭발 | 스케줄링과 유출 |

**사이드 채널 (2단계):** 임플란트가 자리 잡기 전에 익스플로잇 계층은
공용 IP 에코 서비스("내 IP 확인")를 조회한 뒤, 운영자가 제어하는
`/api/ip-sync/sync` 엔드포인트로 POST합니다 — 피해자 주소를 운영자
측 기록과 동기화합니다. 페이지가 IP 에코를 조회한 뒤 이 생소한 POST가
이어지는 것은 정상적인 웹 동작이 아니며, 임플란트 이전의 신뢰할 수
있는 조기 지표입니다.

**임플란트 기동 (3단계):** 첫 생성 도메인은 `CONNECT` 형태로
나타납니다 — 저가 TLD의 15자 랜덤 라벨 도메인, 갓 발급된 인증서.
순식간에 하트비트, 등록, 앱 목록, 모듈 다운로드가 이어집니다.

**앱 트리거형 유출 (4단계):** 안정 상태는 조용한 하트비트/이벤트
루프입니다; **피해 앱을 실행하면 유출이 폭발합니다.** 포획 세션에서
암호화폐 지갑 앱(imToken)을 열자 즉시 `/event` 보고 폭발, 대량
업로드 엔드포인트(`/nb`)로 **1.8 MB** 암호화 POST, 이어지는
**624 KB** POST가 발생했습니다. 페이로드는 암호화 컨테이너이며,
포렌식 신호는 내용이 아니라 크기와 타이밍입니다.

**"미상" 호스트 판별** — 악성이 아닌 호스트를 잘못 귀속하면 노력만
낭비합니다:

| 호스트 유형 | 판정 | 이유 |
|-------------|------|------|
| 인증서 발급기관의 OCSP/CRL 엔드포인트 | 합법 | 갓 발급된 인증서의 표준 TLS 검증 |
| 공용 IP 에코 서비스 | 서비스는 합법, 사용은 악의적 | 정찰 사이드 채널 |
| 운영자 동기화 호스트 | 악성 | 운영자 기록 관리 |
| 15자 랜덤 라벨 저가 TLD 도메인 | 악성 | 임플란트의 도메인 생성 메커니즘 산출물 |

**POST 크기 프로파일:**

| 엔드포인트 | 일반적인 크기 | 비고 |
|------------|----------------|------|
| `/event` | 0.5–0.7 KB | 고빈도 |
| `/a` | 약 1.3 KB | 등록 시 1회 |
| `/u` | 약 1 KB | 주기적 갱신 |
| `/nb` | **1.8 MB / 624 KB 관측** | 대량 유출, 앱 트리거 |
| `/ub` | 소형 | 보조 업로드 경로 |

**포렌식 체크리스트:**

1. 조용한 루프의 기준선 확보: 주기적 `GET /vhx → OK`와 소형 암호화
   POST가 임플란트의 안정 상태 하트비트입니다.
2. 폭발과 앱 실행의 상관 분석 — 지갑 앱 실행 수 초 후의 1.8 MB
   암호화 POST는 거의 결론적입니다.
3. 도메인 형태 주시: 기기가 접속한 15자 랜덤 라벨 저가 TLD 도메인은
   캠페인의 생성 도메인 패턴과 일치합니다.
4. 사이드 채널 주시: IP 에코 조회 후 `POST /api/ip-sync/sync`가
   이어지면 임플란트 이전에 캠페인을 식별할 수 있습니다.
5. CA를 좇지 말 것 — OCSP/CRL 트래픽은 인증서 인프라가 정상적으로
   동작하는 것입니다.

## 3. 페이로드 모듈 — 기능 및 탐지

| 기능 | 관련 모듈 | 비고 |
|------|-----------|------|
| 지갑 탈취 | 19개 지갑 모듈 | 시드 문구, 개인 키, 앱 데이터 |
| 사진 앨범 탈취 | 코어 + 대량 업로드 | 암호화 컨테이너가 `/nb`로 전송 |
| SMS / SIM | `sms.js` | 전화번호, SIM 유무/유효 상태, 통신사 |
| WhatsApp | `wap.js` | 채팅 데이터베이스 접근 |
| 지속성 / 코어 | `new.js` (CorePayload.dylib) | SpringBoard 주입, 스케줄링 |
| 설정 및 다운로드 | `helion.js` | `config.json` 수신기, 모듈 다운로더 |

임플란트는 C2를 통해 암호화 모듈을 가져와 실행 중인 프로세스에
주입합니다; 다운로드는 **지연 로딩** 방식입니다 — 먼저 설치된 앱을
조사한 뒤(`/u`) 일치하는 모듈만 가져옵니다.

### 19개 지갑 대상

| 생태계 | 지갑 |
|--------|------|
| EVM / 멀티체인 | MetaMask, Trust Wallet, imToken, BitKeep, OKX, Global Wallet, Krystal, Coin98, Bitpie, Exodus |
| Solana | Phantom, Solflare |
| TON | TON Keeper, MyTonWallet, TonHub |
| Tron | TronLink |
| DEX / 기타 | Uniswap, Ronin |

각 지갑 모듈은 해당 앱의 샌드박스 데이터 — 키 저장소, 시드 문구
백업, 환경설정 — 를 수확하여 대량 업로드 채널로 보냅니다.

### 사진 앨범 유출

- 사진은 전송 전에 암호화·압축된 컨테이너(7z 유래 포맷)에
  패키징됩니다.
- 관측된 배치는 컨테이너당 수백 장 수준의 사진을 담습니다.
- 컨테이너는 대량 업로드 엔드포인트(`/nb`)를 통해 전송되며, 포획
  세션의 대형 암호화 POST와 일치합니다 (§2).

### 지원 iOS 버전

| iOS 범위 | 익스플로잇 체인 (관측된 단계 이름) |
|----------|-------------------------------------|
| 13.0–14.x | buffout → breezy |
| 15.0–15.5 | jacurutu → VariantB |
| 15.6–16.1 | bluebird → seedbell |
| 16.2–16.5 | terrorbird → seedbell |
| 16.6–17.2 | cassowary → seedbell_pre → seedbell_17 |

페이로드 manifest는 버전/아키텍처별 항목을 담고 있으며(포획
캠페인에서 19쌍), 툴킷은 피해자의 정확한 OS에 맞는 빌드를 전달
합니다. manifest 내부의 버전 지원 플래그는 샘플 비교 시 캠페인
세대를 빠르게 구별해 줍니다.

### 탐지 및 위협 헌팅

- **프로세스 주입**: 비-시스템 경로에서 SpringBoard나 powerd로
  로드되는 dylib.
- **파일 아티팩트**: 앱 쓰기 가능 위치의 암호화된 `.dat` 컨테이너와
  스테이징된 페이로드 파일; 아카이브 형식 바이너리를 반환하는
  `.js` URL.
- **행위 기반**: 지갑 앱 실행 수 초 이내, 갓 등록된 도메인으로의
  대형 암호화 업로드.
- **YARA 후보**: 포획된 바이너리에 내장된 특유의 magic 값과 알고리즘
  상수가 이 계열의 신뢰할 수 있는 시그니처 재료입니다(구체적 수치는
  본 문서에서 공개하지 않음).

탈취에 부합하는 구성입니다. iOS 릴리스별로 체인을 유지 관리하는

제품**으로 이해하는 것이 가장 적절합니다: 운영자는 시드와 도메인을
순환하지만 핵심 플랫폼을 재사용합니다.
