## 이 문서는 무엇인가

실제 워터링홀(watering-hole) 캠페인에서 관측된 상업급 iOS 익스플로잇
툴킷 **Coruna**에 대한 심층 연구입니다. 이 툴킷은 WebKit 익스플로잇을
연결해 iOS 13–17에서 완전한 기기 장악을 수행한 뒤, 23개 모듈로
구성된 스파이웨어 시스템을 배포합니다 — 암호화폐 지갑, SMS,
WhatsApp, 사진 앨범까지 — 그리고 도메인 생성 알고리즘(DGA) 뒤에
C2 통신 트래픽을 숨깁니다.

본 연구는 포획된 툴킷 샘플에 대한 분석에 기반합니다. *"무엇이
전달되었는가"*를 넘어, 이 문서는 그다음 질문에 답합니다: 임플란트는
어디에 연결되는가(완전히 역설계된 DGA), 트래픽은 어떤 모습인가
(C2 프로토콜과 90-요청 포렌식 타임라인), 기기에서 악성코드는 무엇을
하는가(모듈 시스템과 앱 트리거형 유출).

## 주요 기능

| 기능 | 세부 사항 |
|------|-----------|
| 지원 iOS 버전 | iOS 13.0–17.2.1, 버전별 익스플로잇 체인 (WebKit 메모리 커럽션 → PAC 우회 → 샌드박스 탈출) |
| 지갑 탈취 | 19개 지갑 앱 — MetaMask, imToken, Trust Wallet, TronLink, BitKeep, TON Keeper, Uniswap, Phantom, MyTonWallet, Exodus, Ronin, Krystal, TonHub, Global Wallet, Coin98, Bitpie, Solflare, OKX (EVM / Solana / TON / Tron / Ronin) |

| 사진 앨범 탈취 | 기기 사진을 암호화된 `.dat` 컨테이너(7z 유래 포맷)로 패키징하여 대량 유출 |

## 공격 체인 개요

```
피해자가 워터링홀 페이지(위조 등록 사이트) 접속
  └─ 숨겨진 iframe이 난독화된 로더 JS를 로드
      ├─ 1단계 — WebKit / WASM 메모리 커럽션 → 읽기/쓰기 프리미티브
      ├─ 2단계 — PAC 우회 (A12+ 기기)
      └─ 3단계 — 샌드박스 탈출 + 메모리 내 Mach-O 로더
          └─ bootstrap.dylib가 .min.js 페이로드 복호화/다운로드
              └─ powerd / SpringBoard 주입으로 지속성 확보
                  └─ DGA 도메인 C2 트래픽
                      └─ 23개 주입 모듈 → 지갑 / SMS /
                         WhatsApp / 사진 앨범 탈취
```

## 핵심 발견 (TL;DR)

1. **4개 암호화 계층, 전부 정적 키.** 페이로드 파일은 30개 키
   계층을 갖는 ChaCha20(DJB 변형)과 커스텀 `F00DBEEF` 컨테이너
   포맷으로, 런타임 모듈은 7z AES-256으로, C2 트래픽은
   AES-256-ECB로 보호됩니다. 모든 키는 샘플에 내장되어 있거나
   오프라인으로 유도 가능합니다 — 기기별 비밀은 전혀 없습니다.
2. **DGA는 완전히 재현 가능.** 비표준 MurmurHash2 변형이 BSD libc
   `random()`의 시드로 사용됩니다; 도메인 하나를 만드는 비용은
   해시 1회, 딜레이 소진 1회, 난수 15회 추출입니다. 샘플에 내장된
   시드로 예측한 도메인은 포획된 트래픽과 정확히 일치합니다.
3. **C2 프로토콜은 소규모·비대칭적.** 평문 `/vhx` 하트비트,
   타임스탬프 유도 키로 암호화된 Base64 AES-256-ECB POST 본문,
   고정 크기의 작은 확인 토큰.
4. **유출은 앱 트리거 방식.** 포획 세션에서 암호화폐 지갑 앱을
   실행하자 즉시 하트비트 폭발과 두 번의 대형 암호화 업로드
   (1.8 MB, 624 KB)가 발생했습니다; 사진 앨범도 같은 대량
   채널을 사용합니다.
5. **23개 주입 모듈 중 19개가 지갑 대상**이며 다섯 생태계를
   아우르고, WhatsApp, SMS, 사진 앨범, SpringBoard 코어 페이로드가
   추가됩니다 — 국가급 첩보가 아닌 대여 가능한 감시 제품입니다.

## 1. 암호화 스택

| 계층 | 보호 대상 | 알고리즘 | 키 재료 |
|------|-----------|----------|---------|
| A | 페이로드 파일 (`.min.js`) | ChaCha20 (DJB 변형) | 30개 키 계층, 전달 페이지와 샘플에 내장 |
| B | 파일 컨테이너 포맷 | 커스텀 `F00DBEEF` 포맷 | — (구조만) |
| C | 런타임 모듈 (`.7z`) | 7z AES-256 | 캠페인 전체 고정 비밀번호 1개 |
| D | C2 트래픽 | AES-256-ECB | 내장 접두어 + 타임스탬프로 유도 |

가장 중요한 방어적 발견: **기기별 또는 세션별 비밀이 전혀 필요하지
않다는 점입니다.** 이 스택은 전송 난독화일 뿐, 샘플 보유자에 대한
실질 기밀성은 없습니다.

### 1.1 A 계층 — ChaCha20, DJB 변형

페이로드 파일은 표준 IETF ChaCha20가 *아닙니다*. `bootstrap.dylib`
내부(오프셋 `0xad8c`)의 구현은 원조 DJB 변형입니다:

- 64비트 카운터, 64비트 nonce(실제로는 전부 0)
- 모든 평문의 시작에 magic `0x0BEDF00D`
- 8바이트 헤더 이후 원시 XZ/lzma 스트림

표준 라이브러리를 96비트 nonce로 사용하면 쓰레기값이 나옵니다 —
이 툴킷을 리버싱할 때의 전형적인 실패 패턴입니다.

**키 계층 (3단계):**

```
1단계 — 마스터 키 (1개): group.html의 난독화된 uint32 배열이
          platformModule.init()에 전달; 16자 JS 문자열로 디코딩
          후 UTF-16LE 저장 → 32바이트 키. manifest를 해제.
2단계 — OS별 페이로드 키 (19개): 복호화된 manifest 내부, 오프셋
          0x120부터 항목당 100바이트. iOS 버전/아키텍처 조합당
          페이로드 1개.
3단계 — 서브 manifest 키 (10개): 각 페이로드 컨테이너의 type-0x07
          항목(468바이트), 오프셋 0x0108. 공유 모듈.
```

manifest 항목 레이아웃:

```
0x00–0x1F : 32바이트 ChaCha20 키 (파일당 1개)
0x20–0x27 : 파일 크기 (LE64)
0x28      : 항목 유형 (0x01 = 파일, 0x07 = 서브 manifest)
0x29–0x3F : 패딩
```

**off-by-one 함정:** 참조 구현은 manifest 키 테이블을 복호화할 때
`size - 1` 바이트를 해싱합니다. 순진하게 "정리된" 재구현이 테이블
전체를 해싱하면 마지막 항목에서 잘못된 키를 만듭니다 — 1바이트
차이가 전체 파이프라인을 조용히 망가뜨립니다.

### 1.2 B 계층 — F00DBEEF 컨테이너

```
0x00–0x03 : 0BEDF00D            magic
0x04–0x07 : 0000000A            버전
0x08–0x0B : 세그먼트 수 (LE)
0x0C–0x0F : 00000001            헤더 크기
0x20–..   : 세그먼트 테이블 (항목당 16바이트)
```

관측된 세그먼트 유형: `0x01` 코드, `0x02` 설정, `0x03` 문자열,
`0x07` 서브 manifest(키 재료), `0x09` 리소스.

### 1.3 C 계층 — 7z 모듈 전송

설치 후 임플란트는 `/details/<이름>.js` 엔드포인트에서 **하나의
고정된 캠페인 공용 비밀번호**로 암호화된 7z 아카이브를 가져옵니다
— 비밀번호는 바이너리에 상수로 내장되어 있고, 기기별·세션별이
아니며 모듈과 캠페인 스냅샷 전체에서 재사용됩니다. 값은 여기에
게시하지 않습니다.

### 1.4 D 계층 — AES-256-ECB C2 트래픽

```
key       = SHA256(<모든 샘플에 내장된 16자 고정 접두어> + x-ts)[:32]
plaintext = <x-ts 타임스탬프 문자열> + <JSON 페이로드>
padding   : PKCS7
transport : POST 본문에 Base64(암호문), 타임스탬프는 x-ts 헤더로 전달
response  : Base64(16 랜덤 바이트) — 24자 확인 토큰
```

타임스탬프가 평문(`x-ts` 헤더)으로 전달되기 때문에 세션을 관측하는
누구나 — 또는 샘플을 보유한 누구나 — 모든 요청 키를 유도할 수
있습니다. JSON에 ECB를 사용하면 블록 수준 반복 패턴도 노출됩니다.

### 1.5 평가

- **낮은 기밀성, 높은 난독화** — 가벼운 검사와 단순한 게이트웨이
  스캔만 우회합니다.
- **ECB 오용**으로 트래픽 핑거프린팅이 가능합니다.
- **off-by-one 특이점과 DJB nonce 변형은 신뢰할 수 있는 구현
  핑거프린트**로, 다른 캠페인에서 Coruna 계열 툴을 식별할 수
  있습니다.

## 2. DGA — 알고리즘 역설계

Coruna 임플란트는 하드코딩된 C2 목록을 휴대하지 않습니다. 단 하나의
32자리 16진수 시드를 내장하고 필요할 때 도메인을 생성합니다. 살아있는
도메인 하나를 차단해도 호스트 하나만 사라질 뿐입니다. 전체 시퀀스를
예측하면 DGA를 방어 자산으로 뒤집을 수 있습니다.

도메인 하나를 생성하는 정확한 비용:

```
1회 murmurhash2_coruna(캠페인 ID)   → RNG 시드
1회 딜레이 소진                      → 10개 uint16 슬롯 중 1개 소비
15회 random()                        → 라벨 문자
```

결과는 15자 소문자 `[a-z0-9]` 라벨이며, 저가 일회용 TLD(포획
캠페인에서는 `.icu`) 아래에 붙습니다.

### 2.1 비표준 MurmurHash2

```python
MURMUR_M = 0x5BD1E995
MURMUR_INIT = 0x12345678          # 표준 0 시드가 아님

def murmurhash2_coruna(data: bytes, h: int = MURMUR_INIT) -> int:
    h ^= len(data)                # 초기화가 참조 MurmurHash2와 다름
    for i in range(0, len(data) - (len(data) & 3), 4):
        k = int.from_bytes(data[i:i+4], "little")
        k = (k * MURMUR_M) & 0xFFFFFFFF
        k ^= k >> 24
        k = (k * MURMUR_M) & 0xFFFFFFFF
        h = (h * MURMUR_M) & 0xFFFFFFFF
        h ^= k
    tail = data[len(data) & ~3:]
    if len(tail) >= 3: h ^= tail[2] << 16
    if len(tail) >= 2: h ^= tail[1] << 8
    if len(tail) >= 1:
        h ^= tail[0]
        h = (h * MURMUR_M) & 0xFFFFFFFF
    h ^= h >> 13
    h = (h * MURMUR_M) & 0xFFFFFFFF
    h ^= h >> 15
    return h
```

### 2.2 BSD libc random(), TYPE_3

임플란트는 단순 LCG가 아닌 BSD libc의 `random()`을 사용합니다:

```python
class BSDRandom:
    """BSD libc random(), TYPE_3 (31-워드 상태)."""

    DEG_3, SEP_3 = 31, 3

    def __init__(self, seed: int):
        self.state = [0] * self.DEG_3
        self.state[0] = seed & 0xFFFFFFFF
        word = seed & 0xFFFFFFFF
        for i in range(1, self.DEG_3):
            # 상태 초기화에만 쓰이는 Schrage-안전 LCG
            hi, lo = divmod(word, 127773)
            word = ((16807 * lo - 2836 * hi) & 0x7FFFFFFF) or 0x7FFFFFFF
            self.state[i] = word
        for _ in range(310):       # 워밍업 폐기
            self.next()

    def next(self) -> int:
        i, j = 0, self.SEP_3
        word = 0
        while word & 0x80000000 == 0:
            i, j = 0, self.SEP_3
            word = (self.state[i] & 0x7FFFFFFF) + self.state[j]
            self.state[i] = word
            i = j if (i := (i + 1) % self.DEG_3) == 0 else i
            j = j + 1 if (j := (j + 1) % self.DEG_3) == 0 else j
        return (word >> 1) & 0x7FFFFFFF
```

재구현은 어렵지 않습니다 — 하지만 TYPE_3이고 310회 워밍업이 있다는
사실을 *알아야* 합니다. "그냥 rand()겠지"라고 추측하면 절대 일치하지
않는 도메인이 나옵니다.

### 2.3 라벨 생성

```python
LABEL_CHARS = "abcdefghijklmnopqrstuvwxyz0123456789"

def generate_domain(rnd: BSDRandom, tld: str = "icu") -> str:
    label = "".join(LABEL_CHARS[rnd.next() % len(LABEL_CHARS)]
                    for _ in range(15))
    return f"{label}.{tld}"
```

임플란트는 10개의 딜레이 슬롯(uint16 값)을 유지하며 도메인 생성마다
슬롯 하나를 소비합니다 — 자기 제한형 스로틀링 메커니즘입니다.

### 2.4 위치와 검증

DGA 구현은 Mach-O 페이로드의 비-내보내기 함수 영역에 있으며,
캠페인 시드는 세대마다 고정 오프셋에 있습니다(관측된 두 캠페인
스냅샷은 서로 다른 시드 사용 — 운영자는 알고리즘이 아니라 시드를
순환). 시드 값은 게시하지 않습니다.

검증: 포획 캠페인의 Mach-O에서 추출한 시드로 재구현을 실행한 결과,
포획 트래픽에서 관측된 도메인 시퀀스를 정확히 재현했습니다 — 첫
번째 생성 도메인이 기본 C2 호스트와, 두 번째가 모듈 다운로드
호스트와 일치했습니다. DGA는 완전히 결정적입니다: Coruna 샘플을
확보한 방어자는 공격자가 도메인을 등록하기 전에 캠페인의 전체
미래 도메인 목록을 열거할 수 있습니다.

### 2.5 방어 플레이북

1. 포획 샘플에서 시드를 추출합니다(세대마다 고정 오프셋).
2. 위 알고리즘으로 시퀀스를 재생성합니다 — 도메인당 비용: 해시
   1회, 딜레이 소진 1회, RNG 15회(마이크로초 단위).
3. 아직 등록되지 않은 도메인을 포함해 전체 목록을 DNS 계층에서
   차단 목록/싱크홀에 등록합니다.
4. 15자 랜덤 `[a-z0-9]` 라벨 패턴과 일치하는 신규 등록 저가 TLD
   도메인에 알림을 설정합니다.

### 구현 핑거프린트

- `0x12345678` 시드 상수와 `h ^= len(data)` 초기화를 사용하는
  MurmurHash2.
- 310회 워밍업을 갖춘 BSD `random()` TYPE_3.
- 도메인 생성에 연동된 딜레이 슬롯 스로틀링.
- 저가 TLD의 15자 `[a-z0-9]` 라벨.

## 3. C2 프로토콜

9개 엔드포인트, 평문 하트비트 1개, 나머지는 전부 암호화 POST —
의도적으로 최소화되어 있고 회선상 지문화하기 쉽습니다.

| 엔드포인트 | 메서드 | 용도 | 본문 |
|------------|--------|------|------|
| `/vhx` | GET | 하트비트 | 평문 `OK` 응답 |
| `/a` | POST | 등록 / 체크인 | 암호화 |
| `/event` | POST | 이벤트 보고 | 암호화 |
| `/u` | POST | 설치된 앱 목록 | 암호화 |
| `/nb` | POST | 대량 업로드 (사진, 대용량 데이터) | 암호화 |
| `/ub` | POST | 단일 업로드 | 암호화 |
| `/details/<모듈>` | GET | 모듈 다운로드 (7z 아카이브) | — |
| `/api/ip-sync/sync` | POST | 운영자 측 IP 동기화 | 암호화 |
| `/config` | POST | 설정 송수신 (`config.json`) | 암호화 |

```
클라이언트                                     서버
  │                                              │
  │  POST /a (또는 /event /u /nb /ub …)          │
  │  헤더:   x-ts: <unix 초>                     │
  │  본문:   Base64( AES-256-ECB(                │
  │           key = SHA256(PREFIX + x-ts)[:32],  │
  │           pt  = x-ts ‖ JSON,                │
  │           pad = PKCS7 ) )                    │
  │─────────────────────────────────────────────>│
  │                                              │
  │  200 OK                                       │
  │  본문: Base64( 16 랜덤 바이트 )               │
  │<─────────────────────────────────────────────│
```

`PREFIX`는 캠페인의 모든 샘플에 컴파일된 고정 16자 상수이며, 값은
게시하지 않습니다(샘플 보유자는 키 유도 호출 인근의 문자열 상수에서
추출 가능).

**이 설계가 약한 이유:**

- 타임스탬프가 평문으로 전달되므로 네트워크 관측자 누구나 모든
  요청 키를 유도할 수 있습니다 — 가벼운 페이로드 검사만 막을 뿐입니다.
- JSON에 AES-256-**ECB**를 사용하면 블록 수준 반복이 노출됩니다.
- 16랜덤바이트 확인 토큰은 정보를 담지 않습니다; 응답에 고정되고
  식별 가능한 크기(24 Base64 문자)를 부여하기 위해서만 존재합니다.
- 등록에 안정적인 기기 식별자가 포함되어 도메인 순환에도 임플란트
  세션이 추적 가능합니다.

**하트비트 수명 주기:** 임플란트는 주기적으로 현재 DGA 도메인에
`GET /vhx`를 보냅니다; 살아있는 서버는 평문 `OK`로 응답합니다.
실패하면 DGA 커서를 앞으로 옮겨(딜레이 슬롯 1개 소비) 다음 생성
도메인에서 재시도합니다 — 도메인 차단 이후에도 도달 가능하게 유지하는
"데드맨 스위치"이자 수동 DNS 모니터링에 노출시키는 비컨입니다.

**모듈 획득:** 일반 `GET` 요청이 7z 암호화 아카이브를 반환합니다.
모듈은 지연 로딩됩니다 — 해당 피해 앱이 감지되거나 실행된 뒤에만
요청하므로, 캡처 내 모듈 트래픽은 피해자의 설치된 앱 목록을 직접
반영합니다.

**설정 채널:** `helion.js`는 모듈별 설정, 스케줄링 파라미터, 도메인
커서 상태를 담은 JSON 블롭을 관리하며 디스크에 캐시합니다; 변경은
재배포 없이 효력을 갖습니다.

**탐지 시그니처:**

- 주기적인 평문 `GET /vhx` → `OK` 교환.
- 순수 고엔트로피 Base64 POST 본문과 수치형 `x-ts` 헤더.
- 고정 크기 24자 응답 본문.
- 7z 아카이브를 반환하는 `GET /details/<이름>.js` 요청.
- 피해 앱 실행 직후의 암호화 POST 폭발.

## 4. 트래픽 포렌식 — 90-요청 타임라인

워터링홀 페이지부터 안정 상태의 C2까지 — 전체 감염 세션이 분석용으로
포획되었습니다(약 90개 요청). 전체 수명 주기를 축소판으로 보여줍니다.

| 단계 | 트래픽 | 드러나는 것 |
|------|--------|-------------|
| 1. 전달 | 워터링홀 페이지 + 숨겨진 iframe 자산 | 유인책과 익스플로잇 로더 |
| 2. 인프라 | IP 에코 조회, OCSP/CRL 확인, 운영자 동기화 호스트 | 정찰 및 사이드 채널 기록 |
| 3. 임플란트 기동 | 첫 DGA 도메인 접촉, 등록, 앱 목록, 모듈 다운로드 | 임플란트가 깨어남 |
| 4. 안정 상태 | 하트비트 루프 + 이벤트 보고, 피해 앱 실행 후 폭발 | 스케줄링과 유출 |

**사이드 채널 (2단계):** 임플란트가 자리 잡기 전에 익스플로잇
계층은 공용 IP 에코 서비스("내 IP 확인")를 조회한 뒤, 운영자가
제어하는 `/api/ip-sync/sync` 엔드포인트로 POST합니다 — 피해자
주소를 운영자 측 기록과 동기화합니다. 페이지가 IP 에코를 조회한
뒤 이 생소한 POST가 이어지는 것은 정상적인 웹 동작이 아니며,
임플란트 이전의 신뢰할 수 있는 조기 지표입니다.

**임플란트 기동 (3단계):** 첫 DGA 생성 도메인은 `CONNECT` 형태로
나타납니다 — 저가 TLD의 15자 랜덤 라벨 도메인, 갓 발급된 인증서.
순식간에 하트비트, 등록, 앱 목록, 모듈 다운로드가 이어집니다.

**앱 트리거형 유출 (4단계):** 안정 상태는 조용한 하트비트/이벤트
루프입니다; **피해 앱을 실행하면 유출이 폭발합니다.** 포획 세션에서
암호화폐 지갑 앱(imToken)을 열자 즉시 `/event` 보고 폭발, 대량
업로드 엔드포인트(`/nb`)로 **1.8 MB** 암호화 POST, 이어지는
**624 KB** POST가 발생했습니다. 페이로드는 AES 암호화 컨테이너이며,
포렌식 신호는 내용이 아니라 크기와 타이밍입니다.

**"미상" 호스트 판별** — 악성이 아닌 호스트를 잘못 귀속하면 노력만
낭비합니다:

| 호스트 유형 | 판정 | 이유 |
|-------------|------|------|
| 인증서 발급기관의 OCSP/CRL 엔드포인트 | 합법 | 갓 발급된 인증서의 표준 TLS 검증 |
| 공용 IP 에코 서비스 | 서비스는 합법, 사용은 악의적 | 정찰 사이드 채널 |
| 운영자 동기화 호스트 | 악성 | 운영자 기록 관리 |
| 15자 랜덤 라벨 저가 TLD 도메인 | 악성 | DGA 산출물 (검증됨, §2) |

**POST 크기 프로파일:**

| 엔드포인트 | 일반적인 크기 | 비고 |
|------------|----------------|------|
| `/event` | 0.5–0.7 KB | 고빈도 |
| `/a` | 약 1.3 KB | 등록 시 1회 |
| `/u` | 약 1 KB | 주기적 갱신 |
| `/nb` | **1.8 MB / 624 KB 관측** | 대량 유출, 앱 트리거 |
| `/ub` | 소형 | 보조 업로드 경로 |

**포렌식 체크리스트:**

1. 조용한 루프의 기준선 확보: 주기적 `GET /vhx → OK`와 `x-ts`
   헤더를 동반한 POST가 임플란트의 안정 상태 하트비트입니다.
2. 폭발과 앱 실행의 상관 분석 — 지갑 앱 실행 수 초 후의 1.8 MB
   암호화 POST는 거의 결론적입니다.
3. 기기가 접속한 15자 랜덤 라벨 도메인은 DGA 알고리즘으로 대조할
   수 있습니다 (§2).
4. 사이드 채널 주시: IP 에코 조회 후 `POST /api/ip-sync/sync`가
   이어지면 임플란트 이전에 캠페인을 식별할 수 있습니다.
5. CA를 좇지 말 것 — OCSP/CRL 트래픽은 인증서 인프라가 정상적으로
   동작하는 것입니다.

## 5. 페이로드 모듈 — 기능 및 탐지

| 기능 | 관련 모듈 | 비고 |
|------|-----------|------|
| 지갑 탈취 | 19개 지갑 모듈 | 시드 문구, 개인 키, 앱 데이터 |
| 사진 앨범 탈취 | 코어 + 대량 업로드 | 암호화된 `.dat` 컨테이너가 `/nb`로 전송 |
| SMS / SIM | `sms.js` | 전화번호, SIM 유무/유효 상태, 통신사 |
| WhatsApp | `wap.js` | 채팅 데이터베이스 접근 |
| 지속성 / 코어 | `new.js` (CorePayload.dylib) | SpringBoard 주입, 스케줄링, DGA 루프 |
| 설정 및 다운로드 | `helion.js` | `config.json` 수신기, 모듈 다운로더 |

임플란트는 C2를 통해 7z 암호화 모듈을 가져와 실행 중인 프로세스에
주입합니다; 다운로드는 **지연 로딩** 방식입니다 — 먼저 설치된 앱을
조사한 뒤(`/u`) 일치하는 모듈만 가져옵니다.

### 19개 지갑 대상

| 생태계 | 지갑 |
|--------|------|
| EVM / 멀티체인 | MetaMask, Trust Wallet, imToken, BitKeep, OKX, Global Wallet, Krystal, Coin98, Bitpie, Exodus |
| Solana | Phantom, Solflare |
| TON | TON Keeper, MyTonWallet, TonHub |
| Tron | TronLink |
| DEX / 기타 | Uniswap, Ronin |

각 지갑 모듈은 해당 앱의 샌드박스 데이터 — 키 저장소, 시드 문구
백업, 환경설정 — 를 수확하여 대량 업로드 채널로 보냅니다.

### 사진 앨범 유출

- 사진은 PLzma 스타일 SDK로 구축된 커스텀 `.dat` 컨테이너에
  패키징됩니다 — AES 암호화와 LZMA2 압축을 결합한 7z 유래 포맷이며,
  관측 배치에서는 ARM64 BCJ 브랜치 필터(7z coder `0x0a`)가 적용
  되었습니다.
- 관측된 배치는 컨테이너당 수백 장 수준의 사진을 담습니다.
- 컨테이너는 대량 업로드 엔드포인트(`/nb`)를 통해 전송되며, 포획
  세션의 대형 암호화 POST와 일치합니다 (§4).

### 지원 iOS 버전

| iOS 범위 | 익스플로잇 체인 (관측된 단계 이름) |
|----------|-------------------------------------|
| 13.0–14.x | buffout → breezy |
| 15.0–15.5 | jacurutu → VariantB |
| 15.6–16.1 | bluebird → seedbell |
| 16.2–16.5 | terrorbird → seedbell |
| 16.6–17.2 | cassowary → seedbell_pre → seedbell_17 |

페이로드 manifest는 버전/아키텍처별 항목을 담고 있으며(포획
캠페인에서 19쌍), 툴킷은 피해자의 정확한 OS에 맞는 빌드를 전달
합니다. manifest의 `0x04` 플래그 계열이 버전 지원 범위를 표시
합니다 — 샘플 간 이 플래그를 비교하면 캠페인 세대를 빠르게
구별할 수 있습니다.

### 탐지 및 위협 헌팅

- **프로세스 주입**: 비-시스템 경로에서 SpringBoard나 powerd로
  로드되는 dylib.
- **파일 아티팩트**: 앱 쓰기 가능 위치의 암호화된 `.dat` 컨테이너와
  `.min.js` 파일; `.js` URL로 가져오는 7z 아카이브.
- **행위 기반**: 지갑 앱 실행 수 초 이내, 갓 등록된 도메인으로의
  대형 암호화 업로드.
- **YARA 후보**: F00DBEEF magic, DJB ChaCha20 상수 시퀀스,
  MurmurHash2의 `0x12345678` 시드 상수는 모두 신뢰할 수 있는
  바이너리 시그니처입니다.

### 평가

모듈 목록은 제품 카탈로그처럼 읽힙니다: 다섯 생태계에 걸친 19개
지갑에 WhatsApp, SMS, 사진 앨범까지 — 국가급 첩보보다 금전 동기의
탈취에 부합하는 구성입니다. iOS 릴리스별로 체인을 유지 관리하는
상업적 버전 매트릭스와 결합하면, 이 툴킷은 **대여 가능한 감시
제품**으로 이해하는 것이 가장 적절합니다: 운영자는 시드와 도메인을
순환하지만 핵심 플랫폼을 재사용합니다.
